# UX update — 2026-09-29

## Implemented

- Group directory cards contain avatar, name and public/private label. Tapping opens a full-page group information screen with description, member count, join/request state, owner request management and chat access.
- Eligible staff can choose read-only monitoring for public or private groups without the public-group action automatically joining them. Existing backend moderation permissions remain authoritative.
- Map presence uses a small people/count badge at the top right of the spot icon. Badge and spot keep separate tap actions and the geographic anchor stays unchanged.
- Dwell rings use the visual icon diameter instead of the whole marker/label bounds and disappear after server-confirmed completion. Completed visuals stay suppressed for the current app session.
- The server additionally returns `alreadyVisited` for previously credited spots while still requiring fresh dwell for weekly/admin rewards. This lets the new client hide repeated rings after restart without changing XP eligibility.
- The iOS keyboard dismissal toolbar reserves 48 pixels above the keyboard, keeping the chat composer and send button above it.
- Separate gallery and camera controls exist in direct/group chats, global chat and forum replies. Native camera confirmation sends through the existing attachment/send flow. Cancellation sends nothing; failed sends retain the staged attachment. Camera permission text is present on iOS; Android uses a narrowly scoped, non-exported FileProvider.
- Consent verification displays a neutral loading screen. It never shows community content until acceptance is verified, and no longer flashes the agreement form for returning users.

## Package size

The local original APK was a debug artifact of 214,270,717 bytes; it is not a valid production-size comparison with the user's approximately 150 MB build.

- Excluded 16 unused `badge_*.png` files from the bundle: 29,491,977 bytes. The current app draws those category badges in code.
- Converted 27 country badges from 1254-pixel originals to 384×384 WebP (quality 80). They render at up to 96 logical pixels, so 384 covers 4x density.
- Country badge total: 45,355,796 → 777,064 bytes; each is 18,798–33,630 bytes.
- Original PNGs remain in the repository, but are not bundled. The client maps legacy server `.png` badge paths to bundled `.webp` assets.
- Reproducible converter: `tool/optimize_country_badges.cjs`, using sharp through NODE_PATH.
- Final ARM64 release APK: **65,844,726 bytes = 65.8 MB / 62.8 MiB**.
- APK archive inspection confirmed 27 WebP badges, totaling 777,064 bytes, and zero achievement PNGs.

Build command: `flutter build apk --release --target-platform android-arm64 --analyze-size`.
Output: `build/app/outputs/flutter-apk/app-release.apk`.
This is an Android testing build; the project's existing debug signing configuration is unchanged.
