# Проверка XP и достижений

Проверен локальный код. Production не обновлялся, проверки на реальных аккаунтах не выполнялись. 72 серверных теста прошли; это не полный E2E-прогон приложения.

## Исправлено

- Достижения с action=achievement.unlock и objectType=achievement начисляются полностью сверх обычного недельного лимита.
- Обычные начисления ограничены 3000 XP даже при завышенном значении серверной конфигурации.
- В xp_user_weeks confirmedXp остаётся общей суммой для рейтинга; achievementBonusXp хранит бонусы отдельно. Обычный расход лимита равен confirmedXp минус achievementBonusXp.
- Повторная выдача не увеличивает баланс. Отмена и восстановление не освобождают уже использованный обычный лимит.
- Старые pending-достижения с причиной WEEKLY_LIMIT_REACHED могут быть начислены сверх лимита при разрешённых флагах.
- Подтверждённые исторические начисления автоматически не мигрируются. Старые достижения, уже потратившие лимит текущей недели, продолжат учитываться по прежней схеме до смены недели. Для перехода в середине недели нужен отдельный проверенный пересчёт из журнала, а не обнуление счётчиков.

## Найденные проблемы и незавершённые механики

1. Начисление за спот использует текущее содержимое, а не снимок на момент одобрения: telegram_auth_server/lib/xp/spot-xp.js. Позднее добавление фото/описания и повторный sync_spot могут впервые выдать соответствующие этапы XP. Это расходится с исходным правилом «редактирование даёт 0 XP». Проверка deleted отсутствует и в оценщике, и при возобновлении отложенной награды спота.
2. Автоматический отзыв XP при удалении/дисквалификации спота не подключён. Административная отмена существует, но это не автоматическая проверка жизненного цикла контента.
3. settlePendingXp читает только первые 100 pending-операций без пагинации. Если они остаются нерешёнными, следующие могут никогда не обработаться: telegram_auth_server/lib/xp/xp-firestore.js.
4. Собственная история ограничивает запрос 100 документами до сортировки по времени. Это не гарантирует последние 100 начислений: lib/main.dart, XpHistoryScreen.
5. Автоматически подтверждаются только достижения за споты и стаж CCS. Остальные категории есть в каталоге, но available=false. Просмотр каталога не доказывает готовность начислений.
6. Достижения проверяются при открытии/обновлении экрана, не фоновым обработчиком. Момент получения и попадание в недельный рейтинг поэтому зависят от открытия экрана.
7. Календарь 104 недель — план, а не работающий механизм недельных заданий. Серверный прогресс, замена и выдача XP ещё не подключены.

## Расчёт бонусов по текущему каталогу

| Категория | Сумма всех ступеней за всё время |
|---|---:|
| Споты | 1500 XP |
| Посещения | 1275 XP |
| Миты | 2100 XP |
| Активные темы | 1475 XP |
| Стаж CCS | 1650 XP |
| Модератор | 10500 XP |
| Репорты | 725 XP |
| Группы | 3350 XP |
| Турист: 27 стран по 75 | 2025 XP |
| Весь каталог | 24600 XP |
| Без модераторских достижений | 14100 XP |

Это не повторяемый недельный заработок. Каждая ступень выдаётся один раз. Туристические суммы являются суммой каталога: если родная страна исключается, доступный конкретному человеку набор может быть меньше.

Сейчас подключённые споты и стаж суммарно дают до 3150 бонусных XP за всё время. Если у давнего пользователя все эти ступени уже выполнены, но ещё не оплачены, они могут совпасть в одном пересчёте: 3000 обычных + 3150 бонусных = 6150 XP. Это разовый максимум накопившихся подключённых достижений, не недельная норма.

При будущем подключении всех механик чисто арифметический потолок накопившихся бонусов — 27600 XP вместе с обычной неделей, либо 17100 без модераторских. Он предполагает выполнение всех условий, включая 36 месяцев стажа, и не означает возможность выполнить всё за одну неделю.

Обычная неделя без новых достижений: до 3000 XP. Пример недели с одной ачивкой на 750 XP: до 3750 XP. Недельные задания на 300 XP входят в обычные 3000, не прибавляются к ним отдельно.
